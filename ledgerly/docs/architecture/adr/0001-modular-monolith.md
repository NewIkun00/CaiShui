# ADR-0001：V1 使用模块化单体

- 状态：已接受
- 日期：2026-10-07

## 决策

API 使用 NestJS 模块化单体。每个业务模块按 domain、application、infrastructure、presentation 分层；模块私有数据只能经公开应用服务或版本化事件访问。异步任务由独立 Worker 进程消费，但与 API 共用契约和部署版本。

## 原因

早期财税模型仍会快速调整，结账和申报快照又需要强事务一致性。模块化单体能保留边界，同时避免微服务的分布式事务和运维成本。

## 后果

不得跨模块直接查询表。只有出现稳定边界、独立扩容数据和明确运维所有者时，才另建 ADR 讨论拆分。

1.1 目标用户画像

首版核心人群是江苏省一人有限责任公司的老板：公司是增值税小规模纳税人、企业所得税查账征收，主营设计、开发、咨询等现代服务，无存货、无分支机构、无进出口，每月业务笔数较少。他们的共同特征是「三不懂 + 一没有」：

× 01

不懂借贷

听到「借方差、贷方科目、结转」就头大，只会说「我花了一笔钱 / 我收了一笔钱」。

× 02

不懂税种

分不清增值税、企业所得税、个税、附加税、印花税，不知道自己能享受什么减免。

× 03

不懂平台

不知道电子税务局和自然人电子税务局是两个地方，登录后面对几十个菜单不敢点。

同时他们没有全职会计，找代账公司时又容易感到过程不透明；自己处理则担心漏报、错报和公私混同。本产品不试图覆盖所有小微企业，而是先在低复杂度场景中建立「看得懂、可追溯、有人兜底」的信任。

首版不适用：一般纳税人、个体户/个人独资企业、核定征收、建筑与不动产、电商多平台、进出口、差额征税、多员工复杂薪酬、股权交易等场景。详见第 09 章。

1.2 用户要完成的任务（Jobs To Be Done）

① 日常：花 1 分钟把每笔收支记下来，单据随手存档，不丢凭证。

② 随时：能看明白「公司现在有多少钱、别人欠我多少、我今年赚了多少、要交多少税」。

③ 到期：被明确告知「该报什么税、去哪个网站、点哪里、填什么数」，照着做就能完成。

④ 年度：汇算清缴、工商年报不漏不错；想从公司拿钱时知道怎么拿最合规、最省税。

1.4 产品定位与差异化

POSITIONING
一个「会聊天的口袋会计」——
你只管说人话（收了谁的钱、花了什么钱），记账、算税、出表、教你申报，全部交给它。
不做「给会计用的专业软件」，也不做「黑盒代账」；做「让老板用一张任务清单完成一个季度，异常情况可随时转人工」的引导式财税产品。

支点具体做法对应竞品缺口

3.1 数据是怎么一步步变成报表的

会计的本质是一条「流水线」，平台把每一步都自动化，用户只在第 1 步和第 5 步出现：

原始单据发票/回单/合同/工资表
→
交易记录流水：时间/对象/金额/收支
→
记账凭证引擎自动生成借贷分录
→
账簿明细账/科目汇总
→
报表与申报表两表 + 各税种申报数据

3.2 三条必须守住的业务规则

规则一：公是公、私是私。公司账户原则上只走公司业务；对股东、员工的每笔转账必须选择业务性质并关联证据，如工资、报销、借款、出资退回或分红。借款跨年或长期未清时只做风险预警，不自动定性为分红。

规则二：业务和钱分开记、用单据勾稽。开票形成「应收」，收款核销「应收」；垫付形成「欠老板」，报销核销「欠老板」。不靠记忆，靠两笔记录自动配对。

规则三：会计入账与税前扣除分开判断。支出先按真实经济业务入账；是否可税前扣除，再结合真实性、与经营的相关性、合理性、凭证类型和比例限制判断。「有发票」不等于必然可扣，「无发票」也不由系统直接下结论。

04

核心算法与规则引擎

五大引擎的算法设计：主体画像决策、记账规则、税务计算、申报日历、勾稽校验。全部以「规则数据化 + 确定性计算」为主，机器学习只用于辅助分类且必须经用户确认。

4.1 主体画像引擎：一切规则的总开关

用户注册时通过 8–10 个大白话问题完成建档（如「你的营业执照上写的是有限公司还是个体户？」「你去税务局登记时是小规模还是一般纳税人？」），输出一个规则参数包，后续所有引擎都读它：

function buildProfile(answers):
    profile = {}
    // ① 主体类型 → 决定交哪种「所得税」
    if answers.entity in ["一人有限公司", "有限责任公司"]:
        profile.incomeTax = "企业所得税"          // 25% 档，小微实际 5%
        profile.needTwoStatements = true             // 必须出资产负债表+利润表
    elif answers.entity in ["个人独资", "个体户"]:
        profile.incomeTax = "经营所得个税"          // 5%–35% 五级累进
    // ② 增值税身份 → 决定计税方法与发票
    profile.vatType = answers.vatType                    // small / general
    if profile.vatType == "small":
        profile.levyRate = 0.01                         // 3% 减按 1%（至 2027-12-31）
        profile.period = "quarter"; profile.vatThreshold = 300000
    // ③ 地区 → 决定电子税务局入口与地方规则
    profile.region = answers.region                     // 精确到省/市/区县
    profile.etaxPortal = portalMap[answers.province]
    // ④ 准则与征收方式
    profile.accountingStandard = "小企业会计准则"      // 小白默认
    profile.collectionMethod = answers.collection      // V1 仅支持查账
    profile.registeredTaxes = answers.taxRegistration  // 以电子税务局税费种认定为准
    profile.scopeResult = evaluateScope(profile, answers.business)
    if !profile.scopeResult.eligible: return handoffToHuman(profile.scopeResult.reasons)
    return profile

4.2 记账规则引擎：把「人话」翻译成「借贷分录」

用户永远看不到借贷。他录入的是一条交易（方向、对象、业务类型、金额、用哪个账户付、有没有单据），引擎用规则表把它翻译成一张记账凭证（可能多行分录）。核心映射规则：

业务类型怎么自动判断（分类算法）

function classify(tx):
    // 第 1 优先级：用户显式选择（如录入时选了「外包协作」）
    if tx.userChoice: return tx.userChoice
    // 第 2 优先级：硬规则（票据类型/商户关键词/收支方向）
    hit = ruleTable.find(r => r.match(tx))
    if hit: return hit.category
    // 第 3 优先级：该商户的历史习惯（同一收款方上次记成什么）
    if memory[tx.counterparty]: return memory[tx.counterparty]
    // 第 4 优先级：分类模型给出候选（只作建议，不直接入账）
    candidates = mlClassifier(tx)
    if candidates.top.confidence >= 0.9: return confirmWithUser(candidates.top)
    // 仍不确定 → 询问用户；用户的回答沉淀为新规则
    return askUser(tx, candidates)   // 回答后写入 ruleTable / memory
关键设计：分类可以「猜」，但首次入账必须用户确认；只有在「同一对方 + 同一业务类型 + 同一税务属性」的规则经多次确认后，才可允许用户开启自动入账。金额、账户、往来对象等事实字段不由模型虚构，所有模型建议保留来源、置信度与确认人。

4.3 税务计算引擎：每个税种怎么算

① 增值税（V1：小规模纳税人、按季、3% 征收率的现代服务）

function calcVAT(taxEvents, profile, period, ruleVersion):
    rules = policyStore.load(“VAT”, profile.region, period, ruleVersion)
    assert profile.vatType == “small”
    assert taxEvents.every(e => e.baseLevyRate == 0.03)
    // 红字发票、作废、未开票收入均作为独立税务事件，不以发票表直接求和
    normalized = normalizeTaxEvents(taxEvents, rules)
    totalSales = sum(normalized, “assessmentSales”)
    threshold = rules.quarterlyExemptionThreshold
    if totalSales <= threshold:
        taxable = sum(normalized.filter(e => !e.eligibleForSmallScaleExemption), “sales”)
        exempt = totalSales - taxable
    else:
        taxable = totalSales; exempt = 0
    vat = sumByApplicableRate(taxable, normalized, rules) // 减按 1% 或纳税人对某笔放弃减税时的适用率
    return resultWithTrace({vat, exempt, totalSales}, ruleVersion, normalized)
  • 当前政策参数示例：按季申报的小规模纳税人，月销售额 10 万元免税标准换算为季度 30 万元；原适用 3% 征收率的应税销售收入现行减按 1% 至 2027-12-31。
  • V1 若识别到 5% 征收率业务、差额征税、不动产、跨地预缴或其他特殊业务，不继续自动计算，直接转人工。
  • 免税、开具增值税专用发票、放弃减税与红字发票等情形必须分类计算，不能只按「普票/专票」两类硬编码。

② 附加税费（城建税 + 教育费附加 + 地方教育附加）

function calcSurcharges(vatBasis, profile, period, ruleVersion):
    rules = policyStore.load(“SURCHARGES”, profile.region, period, ruleVersion)
    cityRate = rules.cityMaintenanceRate  // 市区 7%；县城/镇 5%；其他 1%
    education = rules.educationSurchargeRate
    localEducation = rules.localEducationSurchargeRate
    reduction = eligibility(profile, “sixTaxesTwoFees”, period) ? rules.reductionFactor : 1
    return round(vatBasis * (cityRate + education + localEducation) * reduction, 2)

③ 企业所得税（按季预缴，累计口径；次年汇算清缴）

function calcIncomeTax(year, quarter, profile, ruleVersion):
    // 申报表填「年初至本季末」累计数，不是只填本季
    cumRevenue = sum(year.to(quarter), "不含税收入")
    cumDeductible = sum(year.to(quarter), "可扣除成本费用")
    cumSurcharge = sum(year.to(quarter), "附加税费")
    accountingProfit = cumRevenue - cumDeductible - cumSurcharge
    estimatedAdjustments = buildTaxAdjustmentEstimate(year.to(quarter))
    taxableIncome = accountingProfit + estimatedAdjustments.increase - estimatedAdjustments.decrease
    avgEmployees = averageByQuarter(year.to(quarter), “employees”)
    avgAssets = averageByQuarter(year.to(quarter), “totalAssets”)
    isSmallProfit = !profile.restrictedIndustry && taxableIncome <= 3000000
                    && avgEmployees <= 300 && avgAssets <= 50000000
    rules = policyStore.load(“CIT”, profile.region, quarter.end, ruleVersion)
    cumTax = calcByPreferentialPolicy(taxableIncome, isSmallProfit, rules)
    payableThisQuarter = cumTax - sum(year.earlierQuarters, "已预缴")
    return max(0, payableThisQuarter)
纳税调整：业务招待费、广告费、捐赠、资产折旧、不合规凭证、个人消费和关联方往来等不能用一个布尔标记代替专业判断。平台在季度做「预计调整」，年度汇算前生成待复核清单，高风险项必须由用户或专业人员确认。

function calcPayrollTax(person, month):
    cumSalary  = sum(year.to(month), "工资")
    deduction  = 5000 * month                        // 基本减除费用
    socialIns  = sum(year.to(month), "社保个人部分")
    addlDeduct = sum(year.to(month), "专项附加扣除")  // 子女教育/房贷/赡养老人等
    taxable = cumSalary - deduction - socialIns - addlDeduct
    cumTax = lookup(BRACKETS, max(0, taxable))       // 查七级预扣率表
    return max(0, cumTax - sum(year.earlierMonths, "已预扣"))

4.4 申报日历引擎：自动排出「全年待办」

function buildCalendar(profile, year):
    tasks = []
    for tax in profile.registeredTaxes:           // 来自税种认定
        for period in periodsOf(tax, year):        // 月/季/年
            deadline = statutoryDeadline(tax, period.end)
            deadline = rollForward(deadline, holidayTable)  // 遇节假日顺延
            tasks.push({tax, period, deadline,
                        status: "pending", amount: null})
    return tasks
// 不自行仅凭法定假日推算最终征期。
// 系统以税务机关当年征期公告为主数据源，日历规则只做交叉校验；不一致时以官方公告为准并发出运营告警。

任务之间有依赖关系，引擎按顺序解锁：数据已结账 → 可申报 → 申报成功 → 生成缴款单 → 缴款成功 → 回传凭证 → 关闭。即使当期没有任何业务，也会生成「零申报」任务——零申报不等于不申报。

4.5 勾稽校验引擎：尽早发现并定位差异

const CHECKS = [
  () => moneyEq(bs.totalAssets, bs.totalLiabilities + bs.totalEquity), // 会计恒等式，按货币精度比较
  () => vouchers.every(v => moneyEq(v.debit, v.credit)),              // 每张凭证借贷平衡
  () => reconcileByAccount(bankLines, ledgerCashAccounts),            // 每个资金账户分别对账
  () => subledgerEq(“AR”, bs.accountsReceivable),             // 应收明细=总账
  () => subledgerEq(“AP”, bs.accountsPayable),                // 应付明细=总账
  () => subledgerEq(“OTHER”, bs.otherReceivables, bs.otherPayables),
  () => taxEventReconciliation(vatReturn, invoices, unbilledSales, redInvoices),
  () => filingSnapshot.ruleVersion != null && filingSnapshot.inputHash != null
]
function verify():
  failures = CHECKS.map(runAndExplain).filter(r => !r.passed)
  return failures.map(locateSourceDocuments) // 一次返回全部差异，不在第一个错误处停止
用户体验：校验在录入、对账、结账和生成申报数据包时分层运行。系统不承诺「永远不错」，而是在申报前列出所有未解决差异、风险级别、源单据和修复建议；存在阻断级差异时不允许进入「可申报」状态。

6.2 日常：给客户开发票

数电票（普票/专票）开具与交付 电子税务局有业务时

  2. 首次使用先做项目信息维护（如把「设计服务」「技术服务」维护好，开票时直接选）。
  3. 点立即开票 → 选择「电子发票」+「普通发票」或「专用发票」→ 确定。
  4. 填购买方信息：名称、纳税人识别号（专票还需地址电话、开户行账号），可从已维护客户中选择。
  5. 选开票项目、填金额；小规模征收率选 1%（留意本季累计是否接近 30 万，接近时本平台会提醒）。
  6. 预览发票核对无误 → 点「发票开具」→ 按提示用个税 APP / 江苏税务 APP 完成身份认证。
  7. 开具成功后选择交付：直接填客户邮箱/手机号推送，或下载 PDF/OFD 自行发送；发票号码由系统自动赋予。

6.3 季度申报（每年 1 / 4 / 7 / 10 月 15 日前，遇节假日顺延）

第一步：增值税及附加税费申报 电子税务局按季
  1. 进入 我要办税 → 税费申报及缴纳 → 增值税及附加税费申报（小规模纳税人）。
  2. 系统按业务复杂度自动匹配模式：确认式申报会把数电票数据自动预填，逐屏核对即可；想自己填可点右上角「我要填表」切换填表式。
  3. 核对三类数：本季不含税销售额、普票对应的免税销售额（季销售额≤30 万部分）、专票对应的 1% 税额。
  4. 附加税费随增值税申报表整合计算；城建税适用 7% / 5% / 1% 取决于纳税人所在地，再结合当期教育费附加、地方教育附加和减免资格计算。
  5. 核对无误 → 申报 → 确认提交。
  6. 立即缴款：已签三方协议直接扣款；也可扫码缴款或打印银行端凭证去银行。
  7. 保存/截图申报成功回执与完税凭证。

完成标志：申报状态「已申报」、扣款状态「已缴款」，回传凭证后本平台任务打勾、应交税费归零。全季没有收入也要零申报。
第二步：企业所得税季度预缴（A 类） 电子税务局按季

第三步：财务报表报送 电子税务局按季
  1. 进入 我要办税 → 财务报表报送（小企业会计准则，季报）。

第四步：印花税（如当期有合同/投资到位） 电子税务局按季或按次

  1. 企业所得税年度申报（次年 5/31 前）：电子税务局进入年度申报，核对官方带出的预缴数据；按本平台「纳税调整待复核清单」逐项判断凭证合规性、限额费用、资产、关联方往来等项目，多退少补。
  2. 工商年报（次年 6/30 前）：登录国家企业信用信息公示系统 → 企业信息填报 → 填报上年度经营情况、资产负债、股东出资、社保人数等并公示；逾期不报会列入经营异常名录。
  3. 个税扣缴手续费退付（次年 3/30 前，可选）：扣缴端可申请按年代扣个税 2% 的手续费返还。
平台支持：年初自动生成「年度结账包」：纳税调整明细表、年报所需财务数据、工商年报填报清单，逐项照抄。

08

合规边界与风险

财税是强监管领域，产品从第一天就要划清「什么能做、什么坚决不做」。合规不是限制，恰恰是这个产品的核心卖点。

红线 01不索取、不保管用户的电子税务局登录密码和短信验证码。登录与提交动作永远发生在官方平台、由用户本人完成；平台不做「把账号给我、我替你报」的黑盒服务。

红线 02不混淆软件工具、代理记账与纳税申报代办。代理记账按财政部门有关规定办理资格；纳税申报代办属涉税专业服务，需遵守机构/人员实名、业务委托信息报送、工作底稿和质量管理等要求。V1 仅提供试算、草稿和引导；任何人工复核或代办服务均由经专项法务审查的合规主体交付。

红线 03不承诺「避税 / 保证少交税」。只依法帮助用户落实应享尽享的优惠（小规模免税、小微 5%），不设计、不教唆虚假申报、虚开发票、个人消费入账等违规操作。

约束 04数据最小化与授权。银行账户、流水、身份与工资信息按敏感信息管理：特定目的、最小必要、单独同意、权限隔离、传输与存储加密；第三方 OCR/AI 处理、模型训练与跨境传输必须单独评估和披露。平台不触碰资金划转权限。

约束 05规则必须可追溯、会过期。每条税率/减免标注政策文号、来源与生效日期（现行 1% 征收率、小微 5% 等优惠执行至 2027-12-31）；到期前提醒复核，过期规则自动失效，绝不拿过期口径算税。

责任 06强制预警公私混同。《公司法》规定，一人有限责任公司的股东不能证明公司财产独立于股东个人财产的，要对公司债务承担连带责任。平台不替混同「打掩护」，反而通过通道选择、借款年底清收、报表留痕帮助用户证明「财产独立」。

责任 07提供纠错路径。申报错了可在电子税务局「申报更正/作废」后重报、多缴可申请退税；每个 SOP 都附异常处理分支，让小白敢下手、也能补救。

责任 08建立电子会计档案能力。原始凭证、记账凭证、账簿、报表、银行对账单、申报表及回执按档案类型管理；保留原始文件、元数据、审签与防篡改记录，支持完整导出、备份恢复和到期鉴定。

约束 09错误责任不靠一句「仅供参考」解决。用户协议需明确用户提供真实数据的义务、平台的计算与提醒责任、人工服务主体、错误通报时限、更正与赔付机制，并评估网络安全与职业责任保险。

产品级风险提示：V1 坚持「规则可追溯 + 专业人员复核 + 用户与官方系统核对 + 用户自主提交」。免责提示不代替质量控制；发现规则错误时必须能定位受影响账套，冻结相关计算，通知用户，生成差异报告和更正路径。
09

适用边界与例外分流

财税产品的首要能力不是「什么都会算」，而是准确识别「哪些可以自动化、哪些必须停下来」。

9.1 V1 准入条件

维度可进入自助流程不符合时
地区江苏省，且已核对当地电子税务局与征期其他省市暂不生成可申报数据包
主体一人有限责任公司个体户、个人独资、合伙企业转人工
增值税小规模纳税人，按季，业务适用 3% 征收率的现代服务一般纳税人、5% 项目、差额征税、预缴业务转人工
所得税企业所得税查账征收，非限制/禁止行业核定征收或复杂纳税调整转人工
经营复杂度无存货、无分支机构、无进出口、无外币命中任一项即终止自动试算
人员无员工或仅股东/法人本人，薪酬场景单一多员工、劳务报酬、股权激励或跨境人员转人工

9.2 三级风险分流

绿色自助可继续：条件在规则覆盖范围内，数据完整，勾稽通过；显示计算过程后由用户确认。

黄色必须人工复核：凭证不完整、金额异常、股东往来、跨期、纳税调整或官方预填差异；未复核前不生成「可申报」状态。

红色拒绝自动化：主体、税种或业务超出产品范围，疑似虚假业务、不当税务安排或数据重大缺失；只提供问题清单与合规求助入口。

9.3 转人工时的交付包

系统不只显示「无法处理」，而是生成结构化工单：主体画像、问题触发规则、原始单据、相关流水、已尝试的计算、差异和待确认问题。复核人的结论与理由回写系统，但不自动泛化为所有客户规则。

10

规则治理与质量保障

产品信任的核心是：每一个数字都有来源，每一条规则都有版本，每一次修改都能找到责任人和受影响用户。

10.1 规则生命周期

政策收录仅官方法律、公告、申报表与税务问答
→

→

→
灰度发布影子计算、新旧版本差异和审批

监控回溯定位受影响账套、回滚、通知与更正

10.3 测试与上线门槛

单元测试：每个公式的临界值、税率切换、生效/失效日、负数与舍入。

黄金样本：由专业人员对真实脱敏账套给出标准结果，覆盖零申报、免税、超阈值、专票、红字票、季中开业、更正申报等场景。

勾稽测试：银行、票据、往来、凭证、账簿、报表、申报表之间双向穿行和差异定位。

发布门槛：关键税额样本必须 100% 通过；任一高风险情形未覆盖时，不得扩大自动化范围。

11

商业验证与核心指标

在扩大开发前，先验证「需求是否足够痛、用户是否信任、是否愿意付费、单户服务成本是否可控」。

11.1 需要回答的四个商业问题

需求：目标老板最想解决的是省钱、省时间、理解财务，还是降低漏报恐惧？每一项的付费意愿不同。

信任：用户要看到哪些证据才愿意把银行流水和发票交给新平台？候选信任件包括合作机构背书、政策引用、逐数解释、安全白皮书和错误赔付。

付费：对「纯工具」、「每季人工复核」、「年度汇算包」分别做价格测试，不只问意愿，要收定金或付费预约。

交付：一户一季度需要多少分钟的人工支持？哪类业务产生最多客服和复核成本？这决定了定价和可扩展性。

11.2 漏斗与单位经济指标

阶段核心指标目的
获客线索成本、到访→注册率、渠道质量验证内容、园区、注册代理和专业机构等渠道
激活建档完成率、首个账户导入率、首次勾稽完成时间判断用户是否在一次使用内获得价值
付费试用→付费率、客单价、退款率、不同套餐选择验证定价而非只追求注册量
交付每户客服分钟、人工复核分钟、OCR/AI/短信/存储成本计算真实毛利和自动化价值
留存下季继续对账率、年度续费率、数据导出/注销率避免季度低频产品只有一次性付费
风险关键税额错误数、更正申报率、人工拦截率、投诉与赔付把安全指标放在增长指标之前

11.3 第一阶段 Go / No-Go

Go：至少 10 家符合 ICP 的付费试点客户；完成一个真实季度；关键税额错误为 0；银行对账完整率 ≥ 99%；单户每季人工复核与客服成本在价格可承受范围内；大多数用户愿意继续下一季度。
No-Go / 重新定位：用户只愿为人工代办付费而不使用自助工具；大量客户不符合窄 ICP；单户人工成本接近传统代账；或仍出现关键税额错误。此时应转向「专业机构工作台」或更窄的试算工具，而不是继续堆功能。
